SlugBase 1.0.0 is the first stable release of the Community Edition. SlugBase is a keyboard-driven bookmark manager where any bookmark can carry a short, private slug that opens through `/go/<slug>`. The Community Edition is open source under AGPL-3.0 and has every feature unlocked. It runs as one container image together with PostgreSQL.

## What is in 1.0.0

**Workspaces and people**

- Workspaces with members and the roles owner, admin and member. You switch the workspace you work in yourself.
- Invitations and teams. Public registration is off by default.
- An audit log of what changed in a workspace.
- Workspace administration for admins and owners: members, invitations, teams, the audit log and the AI switch.
- Instance administration for the operator of a self-hosted installation: workspaces, accounts and instance settings.

**Accounts and sign-in**

- Password sign-in, email verification, password reset and changing your email address.
- Two-factor authentication with an authenticator app and backup codes.
- Sign-in with OpenID Connect providers that the operator sets up.
- A list of your sessions and a way to sign out everywhere else.
- Personal API tokens for scripts and integrations.

**Bookmarks**

- Bookmarks that you create and edit in a dialog, and delete for good.
- Folders, tags that stay private to the member who made them, and pinning.
- Usage tracking, which feeds your most used slugs on the home screen.
- Titles and descriptions read from the page you save.

**Slugs, search and the command palette**

- Slugs that open a bookmark through `go/<slug>` for a signed-in member of the workspace. A slug is never public.
- A choice between several matches for one slug, which SlugBase remembers.
- Adding SlugBase to your browser as a search engine, so that `go mail` in the address bar opens the bookmark with the slug `mail`.
- Global search and the command palette, opened with `⌘K` or `Ctrl K`, which also accepts `go <slug>`.
- A home screen with your counts, most used slugs and pinned bookmarks.

**Sharing**

- Sharing bookmarks and folders with members and with teams.

**Import, export and backup**

- Lossless JSON export and import, and Netscape HTML import and export for browsers and other tools.
- A documented backup and restore for self-hosting: member exports and a database dump.

**AI suggestions**

- Suggestions for a title, a slug and tags, from an AI service that the operator sets up. A workspace admin turns them on or off for the workspace, and each member can opt out.

**Everything else**

- English and German throughout.
- The API under `/api/v1`, with an OpenAPI document and an interactive reference.

## What 1.0.0 does not include

These are left out of version 1 on purpose.

- Public or anonymous slugs, and public share pages. Slugs are private.
- Subdomain or path addresses for each workspace.
- Custom forwarding domains.
- A trash. Deleting a bookmark removes it for good.
- A browser extension or a bookmarklet.
- Reordering by drag and drop.
- A notifications centre. Email covers the few notifications there are.
- AI beyond suggestions for a title, a slug and tags.
- Another database than PostgreSQL.
- A second provider for mail or for AI.
- Backup and restore from the interface. Export and a database dump are the documented way.
- Languages other than English and German.

## Upgrade from 1.0.0-rc.1

Read [Upgrade SlugBase](https://slugbase.app/docs/self-hosting/upgrade) first. It is the guide for every upgrade, and it explains each step below. This is the short form for a `compose.yml` installation. Run the commands in the directory that holds `compose.yml` and `.env`.

1. Take a backup and check that it lists its contents. See [Back Up and Restore SlugBase](https://slugbase.app/docs/self-hosting/backup-restore).
2. Compare your `compose.yml` and `.env` with the `compose.yml` and `.env.example` of this release, and add what is new.
3. Verify the image of this release. The guide shows how to check the signature. The last line of the check prints the image by digest, and that digest is the one at the end of these notes.
4. Set the image you verified in `.env`. Use the line the check printed, so that what you run is what you checked.

   ```sh
   SLUGBASE_IMAGE=ghcr.io/mdg-labs/slugbase@sha256:<the digest>
   ```

5. Pull the image and restart. The server runs the migration first and then starts.

   ```sh
   docker compose pull
   docker compose up -d
   ```

6. Check that it is ready and on the version you expect.

   ```sh
   curl -fsS http://127.0.0.1:3000/ready
   curl -fsS http://127.0.0.1:3000/version
   ```

   `/version` answers with `1.0.0`. Use the `PORT` of your `.env` file if it is not `3000`.

Notes for the upgrade:

- `1.0.0-rc.1` was published before images were signed. 1.0.0 is signed.
- `:latest` and `:1.0` move when a release is published, so pin `SLUGBASE_IMAGE` to `:1.0.0` or to the digest if you want to decide when you upgrade.
- You can roll back by one release. To go back further, or if a rollback does not start, restore the backup from step 1 with the older image. A restore returns the database to the time of the backup.

### Supported PostgreSQL versions

SlugBase supports PostgreSQL 17 and 18, and its tests run against both. `compose.yml` ships PostgreSQL 18. A data volume of one major version does not start under another, so to move to a newer major version you restore a dump into an empty volume. The guide describes it.

## Known limits

- What 1.0.0 does not include, above, is a limit of this release.
- A slug opens the saved address of its bookmark and nothing more. A path or a query after the slug is not passed on.
- SlugBase cannot undo a migration. A rollback is supported for one release only.

## Security

Fixed security issues are listed here by advisory identifier, without detail that would help an attacker. No security advisory had been published when these notes were written, so this release lists none.

To report a vulnerability, do not open a public issue. Use one of these:

- [Report it privately on GitHub](https://github.com/mdg-labs/slugbase/security/advisories/new). This is the preferred way.
- Write to `support@slugbase.app`.

You get an acknowledgement within 3 working days. A fix for a critical or high-severity issue is targeted within 30 days. The advisory is published 7 days after a fixed release is available, and reporters are credited if they wish. The [security policy](https://github.com/mdg-labs/slugbase/security/policy) has the details.
