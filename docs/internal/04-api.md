# SlugBase — API

The HTTP API is the whole product surface: the SPA, the Cloud operator console's product views, API-token scripts and any future browser extension use the same operations. Nothing the UI does is unavailable to an API-token caller with the same rights, and there are no undocumented endpoints (D12).

---

## 1. Contract and tooling

### 1.1 Code-first, generated, committed

| Job | Tool |
|---|---|
| Operation definitions (method, path, params, request and response bodies, errors, security, rate bucket, required role/entitlement) | `@hono/zod-openapi` `createRoute()` with Zod 4 schemas, one file per tag under `packages/server/src/routes/<tag>/` |
| Shared schemas (Bookmark, Folder, Problem, Page, …) | `@slugbase/contracts` — Zod schemas only, no runtime dependencies beyond Zod, importable by the server, the web app and the console |
| OpenAPI document | Generated by `pnpm api:gen` into `packages/contracts/openapi/openapi.json` (CE) and, in the Cloud build, a merged `openapi.cloud.json` that adds the Cloud modules' operations — **committed** |
| Typed client | `openapi-typescript` (types into `packages/contracts/openapi/schema.d.ts`, committed) + `openapi-fetch` runtime wrapper in `packages/web/src/api/client.ts` |
| Lint | Spectral with a SlugBase ruleset: every operation has an `operationId`, a tag, `x-slugbase-auth`, `x-slugbase-rate`, at least one 4xx `application/problem+json` response, and no inline anonymous object schemas in responses |
| Breaking-change check | `oasdiff breaking` against the last `main` tag's committed document; a breaking change in `/api/v1` fails CI (§2.2) |

**Drift check:** CI regenerates `openapi.json` and `schema.d.ts` and fails when the working tree differs (`git diff --exit-code`). A route whose handler returns a body the response schema doesn't describe fails its contract test (§1.3) — the generated document can never describe an API the server doesn't serve.

### 1.2 Route declaration carries the policy

Every route declares, next to its schemas:

```ts
createRoute({
  method: 'post', path: '/bookmarks', tags: ['bookmarks'], operationId: 'createBookmark',
  'x-slugbase-auth': 'member',            // anonymous | account | member | admin | owner | instanceAdmin | machine
  'x-slugbase-entitlement': undefined,    // e.g. 'sharing.teams'
  'x-slugbase-rate': 'write',             // bucket from §7
  'x-slugbase-scope': 'write',            // API-token scope required: read | write
  request: { body: { content: { 'application/json': { schema: BookmarkCreate } } } },
  responses: { 201: …, 400: problem, 403: problem, 409: problem, 422: problem },
})
```

The authorization middleware (doc 01 §4, step 9) reads these extensions — the policy is data the OpenAPI document publishes, not a decorator hidden in a handler. Spectral rejects a route without them.

### 1.3 Contract tests

The integration suite (doc 08 §4) walks the generated document and, for every operation: calls it with a valid fixture and validates the response against its declared schema; calls it unauthenticated, with a too-low role, without the entitlement (Cloud entitlement source fixture) and with a read-only token on a write route, and asserts the declared 401/403 problem type; calls it from workspace B on workspace A's resource and asserts 404.

### 1.4 Reference docs

`GET /api/v1/openapi.json` serves the document; `/api/docs` serves a Scalar reference UI from bundled assets (no CDN, CSP-compatible). Both can be disabled with `API_DOCS_ENABLED=false`; both are on by default in CE and Cloud (the API is public, its document is not a secret).

## 2. Conventions

### 2.1 Paths

| Prefix | Contents |
|---|---|
| `/api/v1/*` | The versioned JSON API |
| `/api/config` | Unversioned bootstrap config for the SPA (§9.1) |
| `/go/<slug>` | Slug forwarding (§9.3) — not under `/api`, because it is typed into the address bar |
| `/health`, `/ready`, `/version` | Process probes (§9.2) — unversioned, never behind auth |
| `/metrics` | Internal port only, never on the public listener |
| everything else | The SPA (`index.html` for any unknown `GET` with `Accept: text/html`; 404 problem otherwise) |

Path segments are lower-case kebab nouns, plural for collections (`/bookmarks`, `/api-tokens`, `/audit-events`). The active workspace is **never** in the path (D11, doc 01 §5) — `/bookmarks` means "bookmarks in the active workspace". The few account-level resources live under `/me`; CE instance administration under `/instance`.

Actions that are not CRUD use a sub-resource noun (`POST /bookmarks/{id}/open`, `POST /invitations/accept`), never verbs in the collection path and never `?action=`.

### 2.2 Versioning

- `/api/v1` is the only version at launch. **Additive changes** (new operation, new optional request field, new response field, new enum value in a response marked `x-extensible-enum`) ship in `v1` without notice. Clients must ignore unknown response fields; the generated client does.
- **Breaking changes** (removed or renamed field, new required request field, narrowed type, changed status code semantics) go to a new `/api/v2` served **alongside** `v1` for at least six months, announced in the changelog and via a `Deprecation` + `Sunset` header on every `v1` response of the affected operations.
- The SPA always targets the newest version and ships with the server, so it never needs the overlap; the overlap is for API-token users and the browser extension (post-1.0).
- `oasdiff` enforces this mechanically (§1.1).

### 2.3 Representation

| Rule | Value |
|---|---|
| Media type | `application/json; charset=utf-8` for requests and responses; `application/problem+json` for errors; `multipart/form-data` only on the import upload |
| Field casing | `camelCase` in JSON; `snake_case` in the database; mapping lives in the repository layer |
| IDs | UUIDv7, lower-case hyphenated strings (`0192f1c4-…`); generated by Postgres 18 `uuidv7()`; time-ordered, so they double as a creation-order tiebreak in keyset pagination. No sequential integers are ever exposed |
| Timestamps | RFC 3339 UTC with millisecond precision (`2026-10-08T09:51:26.123Z`); `timestamptz` in the database |
| Absent vs null | Optional fields are omitted when unset in requests; responses always include declared fields, `null` when empty. `PATCH` distinguishes "omitted" (unchanged) from `null` (clear) |
| Money (Cloud) | Integer minor units plus ISO 4217 currency (`{ "amount": 300, "currency": "EUR" }`) — never floats, never formatted strings in the API |
| Enums | Lower-case snake strings (`owner`, `shared_with_me`, `past_due`) |
| Booleans | Never stringly typed; query-string booleans are `true`/`false` only |
| Unknown fields | Rejected with `422 validation_failed` (Zod `strict`) — a typo never silently does nothing |
| Locale | `Accept-Language` affects only server-rendered messages (problem `detail`, email); data is locale-independent |

### 2.4 HTTP semantics

- `GET` is safe and never changes state (the single exception, recording usage on `/go`, happens asynchronously and is not observable in the response).
- `POST` creates (201 + `Location` + body) or performs an action (200/202/204).
- `PATCH` is JSON Merge Patch semantics on declared fields; `PUT` replaces a whole set (`PUT /teams/{id}/members`).
- `DELETE` is idempotent: deleting an already-deleted resource returns 204, not 404, when the caller could have seen it; a resource the caller never could see is 404.
- **Not found vs forbidden:** a resource in another workspace, or one the caller has no read access to, is **404** — existence is never disclosed. **403** is returned only when the caller can see the resource but may not perform the action (a member deleting a bookmark shared with them).
- **Optimistic concurrency** on editable records: every bookmark, folder, team and workspace response carries `version` (an integer) and an `ETag`; `PATCH`/`PUT` accept `If-Match` and return `412 precondition_failed` on mismatch. The SPA sends it from the edit modal so two tabs don't silently overwrite each other. Optional for API-token callers.

## 3. Errors

### 3.1 Shape

Every error is an RFC 9457 problem document:

```json
{
  "type": "https://slugbase.app/problems/slug_taken",
  "title": "Slug already in use",
  "status": 409,
  "code": "slug_taken",
  "detail": "You already use the slug \"mail\" in this workspace.",
  "requestId": "01J9…",
  "errors": [ { "path": "slug", "code": "slug_taken" } ]
}
```

- `code` is the stable machine identifier; `type` is its URL form; `title` is static per code (English); `detail` is localised by `Accept-Language` and may contain user-supplied values (escaped by the client).
- `errors[]` appears on `validation_failed` and on per-field domain errors, with JSON-pointer-ish `path`s matching the request body.
- `requestId` echoes the `X-Request-Id` response header for support.
- **Never** a stack trace, SQL, an internal identifier the caller couldn't already see, or a hint that distinguishes "no such account" from "wrong password".

### 3.2 Code catalog

| Status | `code` | When |
|---|---|---|
| 400 | `bad_request` | Malformed JSON, wrong content type, body over the route limit |
| 401 | `unauthenticated` | No valid session or token |
| 401 | `mfa_required` | Session exists at `partial` level; complete `POST /auth/mfa/verify` |
| 401 | `reauth_required` | Sensitive operation needs a fresh re-authentication (§4.4) |
| 403 | `forbidden` | Authenticated, can see the resource, may not do this |
| 403 | `cross_site_request` | Origin / Fetch-Metadata check failed (§5) |
| 403 | `token_scope` | API token is read-only, or bound to a different workspace |
| 403 | `entitlement_required` | Plan doesn't include the feature; body carries `entitlement` and, on Cloud, `upgradeAvailable: true` |
| 403 | `email_unverified` | Action requires a verified email (Cloud) |
| 403 | `account_disabled` | Instance admin disabled the account |
| 403 | `registration_closed` | Public registration is off |
| 403 | `setup_completed` | `POST /setup` after setup |
| 404 | `not_found` | Unknown, or not visible to the caller (§2.4) |
| 404 | `slug_not_found` | `/go` and `POST /go/resolve`: no accessible forwarding bookmark |
| 409 | `slug_taken` | The caller already uses this slug in the workspace |
| 409 | `slug_reserved` | Slug is in the reserved list |
| 409 | `name_taken` | Folder, tag or team name already exists for that owner/workspace |
| 409 | `email_taken` | Registration or email change to an address already in use — **only** where the flow is not enumeration-sensitive (invitation to an existing member); registration and email change respond generically instead (doc 02 §2) |
| 409 | `already_member` | Invitation for, or accept by, an existing member |
| 409 | `last_owner` | Removing, demoting or the departure of the last owner |
| 409 | `idempotency_conflict` | Same `Idempotency-Key` with a different request body (§6.3) |
| 409 | `billing_active` | Deleting a workspace/account that owns an active paid subscription (Cloud) |
| 410 | `token_expired` | Verification, reset or invitation token expired or already used |
| 412 | `precondition_failed` | `If-Match` mismatch |
| 413 | `payload_too_large` | Import file over cap |
| 415 | `unsupported_media_type` | |
| 422 | `validation_failed` | Schema validation; `errors[]` lists fields |
| 422 | `bookmark_limit_reached` | Create/import would exceed the bookmark cap; carries `limit`, `used`, and for import `accepted`, `rejected` |
| 422 | `seat_limit_reached` | Invitation accept with no free seat (Cloud) |
| 422 | `workspace_limit_reached` | Creating a workspace beyond the account entitlement |
| 422 | `weak_password` | Fails length/breach policy (Q15) |
| 422 | `invalid_code` | Wrong TOTP or backup code (counts against the MFA bucket) |
| 422 | `url_not_allowed` | URL scheme not `http`/`https`, or host fails egress policy for a fetch |
| 429 | `rate_limited` | With `Retry-After` and `RateLimit-*` headers (§7) |
| 502 | `upstream_failed` | Metadata/AI/billing provider failed; the operation is retryable |
| 503 | `unavailable` | Not ready (migrations pending, DB unreachable), or the port is unconfigured (`mail_unavailable`, `ai_unavailable` as `code`) |
| 500 | `internal` | Everything else; logged with the request ID, reported through the error port |

New codes are additive (§2.2); a client must treat an unknown `code` by its `status`.

## 4. Authentication

### 4.1 Principals

| Principal | Credential | Carries | Cross-site check (§5) | MFA |
|---|---|---|---|---|
| **Session** | `__Host-slugbase_session` cookie | account, active workspace, auth level (`partial` → `full`), re-auth timestamp | Required on unsafe methods | Enforced at login |
| **API token** | `Authorization: Bearer slb_<43 base64url chars>` | account, **bound workspace**, scope (`read` / `write`) | Not applied (no ambient credential) | Not applicable (an already-trusted credential, D10) |
| **Machine** | Route-specific: a module's inbound event endpoint (in Cloud, the billing service's events; no session; sender signature verified, idempotent), internal metrics port | nothing | Not applied | — |
| **Anonymous** | none | — | Required on unsafe methods (login, register, setup, password reset, invitation accept) | — |

When an `Authorization` header is present, cookies are **ignored** for that request — a request is either a token request or a browser request, never both.

### 4.2 API tokens and workspaces

A token is created inside a workspace and **bound** to it: every request made with it acts in that workspace, regardless of the account's session. A token cannot switch workspaces, cannot manage tokens, sessions, MFA, email or password, and cannot reach `/instance/*` — those operations declare `x-slugbase-auth` levels that exclude token principals. A member who loses membership loses every token bound to that workspace (deleted in the same transaction as the membership).

Multi-workspace automation uses one token per workspace. An `X-Slugbase-Workspace` header override is **not** offered at v1 (Q40).

### 4.3 Session levels

- `partial`: password verified, TOTP pending. Only `POST /auth/mfa/verify`, `POST /auth/logout` and `GET /api/config` accept it; everything else returns `401 mfa_required`. Expires after 10 minutes.
- `full`: signed in. The session token is **rotated** on the `partial → full` transition and on every privilege change (role change of the account itself in the active workspace, instance-admin flag change, password change).

### 4.4 Re-authentication ("sudo mode")

Destructive or credential-changing operations require `reauthAt` within the last 10 minutes on the session: change password, change email, disable MFA, regenerate backup codes, create an API token, delete the account, delete a workspace, transfer ownership, change the instance-admin flag. Without it they return `401 reauth_required`; the SPA prompts for password or TOTP (or re-runs OIDC for password-less accounts) via `POST /me/reauth` and retries.

### 4.5 Sign-in flows (shape only — behaviour in doc 02 §2)

| Flow | Calls |
|---|---|
| Password | `POST /auth/login` → `200 { next: "done" }` or `{ next: "mfa" }` (partial session) → `POST /auth/mfa/verify` |
| OIDC | `GET /auth/oidc/{provider}/start?returnTo=` → `302` to IdP (state, nonce, PKCE stored server-side, doc 05 §2.3) → `GET /auth/oidc/{provider}/callback` → `302` to `returnTo` (same-origin paths only) |
| Registration (if enabled) | `POST /auth/register` → generic `202` → email link `/verify-email#token=…` (fragment, so the token never reaches server logs or `Referer`) → SPA calls `POST /auth/verify-email` |
| Password reset | `POST /auth/password/forgot` → generic `202` → link `/reset-password#token=…` → `POST /auth/password/reset` (revokes every session of the account) |
| First run (CE) | `GET /setup/status` → `POST /setup` (single-shot, advisory-locked, doc 05 §3) |

## 5. Cross-site request rules

Applied by middleware before routing (doc 01 §4, step 5) to every `POST`, `PUT`, `PATCH` and `DELETE` that is **not** bearer-authenticated and not a `machine` route:

1. `Origin` must be present and equal `APP_ORIGIN` exactly (scheme, host, port). A missing `Origin` on an unsafe method is rejected.
2. `Sec-Fetch-Site`, when present, must be `same-origin`.
3. `Content-Type` must be `application/json`, except the import route (`multipart/form-data`). This makes every mutation a non-simple request a cross-site HTML form cannot produce.

Failure is `403 cross_site_request`, logged at `warn` with the offending origin. There is **no exemption list** (Q5): login, logout, registration, setup, MFA and reset are protected exactly like everything else, because they are all same-origin calls from the SPA.

No CORS headers are ever emitted on `/api/*`; preflights get `403`. Forms on a separate marketing origin therefore do **not** call the app origin from the browser: the marketing site proxies them same-origin to the server over the internal network, and their routes declare `audience: 'marketing-form'` (Q41; doc 01 §4 step 5).

`GET /go/<slug>` is a safe method and relies on `SameSite=Lax` (sent on top-level navigation from the address bar, not on cross-site subresource requests) plus the fact that it has no side effects beyond the asynchronous usage counter.

## 6. Collections

### 6.1 Keyset pagination

Every list operation is cursor-paginated; there is no offset pagination anywhere.

```
GET /api/v1/bookmarks?sort=recent&limit=48&cursor=eyJr…
→ { "items": [ … ], "nextCursor": "eyJr…" | null, "total": 1234 | null }
```

- `limit`: default per resource (bookmarks 48, others 50), maximum 100.
- `cursor`: opaque, base64url JSON of the last item's sort key and `id`, **HMAC-signed** with a server key so a client can't forge positions or smuggle filter changes; a cursor is valid only with the filter and sort it was issued for (mismatch → `400 bad_request`).
- `total`: returned for bookmarks, folders and tags lists (the UI shows counts), computed by a `count(*)` over the same filter — capped: above 10 000 it returns `null` and `totalAtLeast: 10000` (Q42).
- The UI's page selector (24/48/96) maps to `limit`; "page N of M" is replaced by "load more" and a count, because keyset pagination has no random page access. The design prototype's pager is adapted accordingly (doc 03).

### 6.2 Filtering and sorting

Filters are query parameters named after fields, validated by Zod; repeated keys for multi-value (`?tag=a&tag=b` — AND semantics for tags, OR is not offered). Sorting is `sort=<key>` from a per-resource allowlist; direction is part of the key (`recent`, `oldest`, `title_asc`, `title_desc`, `most_used`, `recently_opened`). Free-text is always `q`.

"Select all across pages" uses `GET /bookmarks/ids` with the same filters, returning up to 10 000 IDs; bulk operations accept either an ID list (≤ 1 000) or the same filter object, so the server never needs the client to round-trip 10 000 IDs (§10.6).

### 6.3 Idempotency keys

Operations that create billable or externally visible effects accept `Idempotency-Key` (a client-generated UUID): **required** on the billable mutations a module declares (in Cloud: checkout, seat changes and cancellation, Cloud doc 06); **accepted** on `POST /invitations`, `POST /import/*`, `POST /bookmarks`. The server stores `(principal, key, operation, request hash) → response` for 24 hours (doc 05 §2.10); a replay returns the stored response with `Idempotency-Replayed: true`; the same key with a different body is `409 idempotency_conflict`; a concurrent duplicate waits on the first via a row lock rather than running twice.

## 7. Rate limits

Token buckets through `RateLimitPort` (doc 01 §8.2). Keys combine the bucket with the client IP (as resolved through trusted proxies) and, when authenticated, the account ID — whichever bucket empties first wins. Responses carry `RateLimit-Policy`, `RateLimit` (IETF draft headers) and, on 429, `Retry-After`.

| Bucket | Applies to | Limit (per IP) | Limit (per account / target) |
|---|---|---|---|
| `login` | `POST /auth/login` | 10 / min | 10 / 15 min per **email** (counted even for unknown emails) |
| `mfa` | `POST /auth/mfa/verify`, `POST /me/reauth` (TOTP) | 10 / min | 5 failures / 15 min per account, then the partial session is revoked |
| `register` | `POST /auth/register` | 5 / hour | — |
| `reset` | `POST /auth/password/forgot`, `/auth/verify-email/resend`, `POST /me/email` | 5 / hour | 3 / hour per target email |
| `token_redeem` | `POST /auth/verify-email`, `/auth/password/reset`, `/invitations/inspect`, `/invitations/accept`, `/me/email/confirm` | 20 / hour | — |
| `token_create` | `POST /me/api-tokens` | — | 20 / hour |
| `setup` | `POST /setup` | 5 / hour | — |
| `go` | `GET /go/*`, `POST /go/resolve` | 600 / min | 300 / min |
| `read` | Every other authenticated `GET` | 1 200 / min | 600 / min |
| `write` | Every other authenticated mutation | 300 / min | 120 / min |
| `bulk` | `POST /bookmarks/bulk`, `/import/*`, `GET /export/*` | — | 20 / hour |
| `fetch` | `POST /bookmarks/metadata`, `GET /favicons/*` (cache misses only) | 120 / min | 60 / min |
| `ai` | `POST /ai/suggestions` | — | 60 / hour per account, 600 / hour per workspace |
| `public` | `GET /api/config` and the public read operations modules declare | 300 / min | — |

All limits are configuration (`RATE_LIMIT_<BUCKET>_*`); the values above are the defaults. Modules may add their own buckets; the Cloud modules do (Cloud docs 06 and 07). Probes (`/health`, `/ready`, `/version`) and `machine` routes are not rate-limited by this port; a `machine` route is protected by its signature check and the deployment's edge rules.

## 8. Response headers

On every API response: `X-Request-Id`, `Cache-Control: no-store`, `Content-Type`, the security headers of doc 01 §4 step 2. On collections: none beyond the body (no `Link` headers). On rate-limited routes: `RateLimit-*`. On editable records: `ETag`. On deprecated operations: `Deprecation`, `Sunset`, `Link: rel="deprecation"`.

## 9. Public and process endpoints

### 9.1 `GET /api/config`

Unauthenticated, cacheable for 60 s (`Cache-Control: public, max-age=60`), the only thing the SPA needs before sign-in:

```json
{
  "apiVersion": "v1",
  "origin": "https://app.slugbase.app",
  "product": { "name": "SlugBase", "version": "1.4.2" },
  "signIn": { "password": true, "registration": true, "oidc": [ { "slug": "google", "name": "Google" } ] },
  "setupRequired": false,
  "locales": ["en", "de"], "defaultLocale": "en",
  "features": { "mail": true, "ai": true, "billing": true, "analyticsConsentRequired": true },
  "legal": { "imprintUrl": "…", "privacyUrl": "…", "termsUrl": "…" }
}
```

`features` reports **whether a port is configured**, never entitlements (those need a workspace — `GET /entitlements`). `billing: true` only means a non-no-op billing adapter is composed; the SPA uses it to decide whether to load the Cloud extension routes' data, not to branch product behaviour (D4).

### 9.2 Probes

| Endpoint | Returns | Notes |
|---|---|---|
| `GET /health` | `200 {"status":"ok"}` | Process alive; no DB access |
| `GET /ready` | `200` / `503` with `{ database, migrations: { expected, applied } }` | DB reachable and migrations at the build's level |
| `GET /version` | `{ name, version, commit, builtAt }` | The deploy gate compares `version` (doc 07 §4) |

### 9.3 `GET /go/<slug>`

Not part of `/api/v1`, but specified here because it is the product's main entry point.

| Situation | Response |
|---|---|
| Not signed in | `302 /login?returnTo=/go/<slug>` |
| Partial session | `302 /login/mfa?returnTo=…` |
| Slug grammar invalid | SPA not-found page (`404`, HTML) |
| No accessible forwarding bookmark | SPA "slug not found" page (`404`, HTML) offering "create a bookmark with this slug" |
| Exactly one match, or a remembered preference | `302 <destination>` with `Referrer-Policy: no-referrer`, `Cache-Control: no-store`; usage recorded asynchronously |
| Several matches, no preference | SPA disambiguation page (`200`, HTML) at the same URL; the SPA calls `POST /api/v1/go/resolve` |
| Extra path or query after the slug (`/go/jira/PROJ-12`) | `404` slug-not-found page; path appending is post-v1 (Q43) |

Only `http:` and `https:` destinations are ever redirected to (enforced on write and re-checked on read); `javascript:`, `data:` and anything else is impossible by construction.
