## Before you dig in

Most production failures come from **environment variables** or **URL mismatch** behind a reverse proxy. Confirm values with [Configuration](/selfhosted/configuration) and [Reverse proxy and HTTPS](/selfhosted/reverse-proxy). For a clean first install, follow [First run setup](/selfhosted/first-run-setup).

<Callout kind="tip">
  Check container or process logs when the server exits immediately or API calls fail—startup validation prints clear errors for missing or weak secrets.
</Callout>

## Server exits on startup

<ExpandableGroup>
  <Expandable title="Error about JWT_SECRET, ENCRYPTION_KEY, or SESSION_SECRET" default-open="false">
    **`JWT_SECRET`** and **`ENCRYPTION_KEY`** are required and must each be at least **32** characters and not the documented placeholder. In **`NODE_ENV=production`**, **`SESSION_SECRET`** is also required (minimum **32** characters). Generate values safely (see [Configuration](/selfhosted/configuration)), update your env file or orchestration secrets, and restart.
  </Expandable>
  <Expandable title="Cannot bind to port / address already in use" default-open="false">
    The server listens on **`PORT`** (default **5000**). Ensure nothing else uses that port, or set **`PORT`** to a free port and point your reverse proxy at it. In Docker, map the host port to the container **`PORT`**.
  </Expandable>
</ExpandableGroup>

## Login, cookies, and HTTPS

<ExpandableGroup>
  <Expandable title="Login works on HTTP but not when using HTTPS (or the reverse)" default-open="false">
    Set **`BASE_URL`** and **`FRONTEND_URL`** to the **exact origin** users use in the browser (including `https://`). Cookies are **Secure** when `NODE_ENV=production` and **`BASE_URL`** starts with `https://`. Mismatched scheme or host breaks sessions. See [Reverse proxy and HTTPS](/selfhosted/reverse-proxy).
  </Expandable>
  <Expandable title="Redirect loops or wrong host behind a proxy" default-open="false">
    The app trusts **one** proxy hop (`X-Forwarded-*`). Your proxy should forward **`Host`**, **`X-Forwarded-Proto`**, and **`X-Forwarded-For`**. Keep **`BASE_URL`** aligned with the public hostname.
  </Expandable>
  <Expandable title="Browser shows CORS errors" default-open="false">
    Set **`FRONTEND_URL`** to your UI origin, or add extra origins in **`CORS_EXTRA_ORIGINS`**. A typical single-container self-hosted build serves the SPA and API on the **same origin**, which avoids CORS. Details in [Configuration](/selfhosted/configuration).
  </Expandable>
</ExpandableGroup>

## Database and data

<ExpandableGroup>
  <Expandable title="SQLite permission or path errors" default-open="false">
    Ensure the process can read and write **`DB_PATH`** (Dockerfile default **`/app/data/slugbase.db`**). Mount a **persistent volume** for the data directory so the file survives container restarts. See [Docker Compose](/selfhosted/docker-compose).
  </Expandable>
  <Expandable title="PostgreSQL connection failures" default-open="false">
    Set **`DB_TYPE=postgresql`** and either **`DATABASE_URL`** or **`DB_HOST`**, **`DB_PORT`**, **`DB_NAME`**, **`DB_USER`**, **`DB_PASSWORD`**. Verify network reachability from the SlugBase container or host. Migrations run automatically on startup.
  </Expandable>
  <Expandable title="I expected Initial Setup but see the normal login instead" default-open="false">
    The database is already initialized. For a true fresh start you need an **empty** database or a new SQLite file path—not a reused volume from an old install. See [First run setup](/selfhosted/first-run-setup).
  </Expandable>
</ExpandableGroup>

## OIDC and email

<ExpandableGroup>
  <Expandable title="OIDC login fails or redirect URI mismatch" default-open="false">
    Provider settings in **Admin → OIDC Providers** must match your IdP. Callback URLs must use the same public **`BASE_URL`** as users (including `https://`). Follow [OIDC](/selfhosted/admin-oidc).
  </Expandable>
  <Expandable title="Password reset emails never arrive" default-open="false">
    Configure SMTP under **Admin → Settings**. Without working outbound mail, reset links cannot be sent. See [SMTP](/selfhosted/admin-smtp).
  </Expandable>
</ExpandableGroup>

## Slugs and `/go/` links

<ExpandableGroup>
  <Expandable title="/go/… returns login or does not resolve" default-open="false">
    Opening a slug requires being **signed in**; unauthenticated users are sent to login first. The bookmark needs **Enable Forwarding** and a unique **Slug**. See [Slugs overview](/selfhosted/slugs-overview) and [Go preferences](/selfhosted/go-preferences).
  </Expandable>
</ExpandableGroup>

## API documentation and health checks

<ExpandableGroup>
  <Expandable title="I want to hide the Swagger UI" default-open="false">
    Set **`SLUGBASE_API_DOCS=false`** to disable the UI at **`/api-docs`**. OpenAPI JSON/YAML routes may still be available unless you restrict them at the proxy. See [Configuration](/selfhosted/configuration).
  </Expandable>
  <Expandable title="Health check through the proxy" default-open="false">
    Request **`/api/health`** through your public URL and expect a successful response when the app is up. Use this for load balancers after following [Reverse proxy and HTTPS](/selfhosted/reverse-proxy).
  </Expandable>
</ExpandableGroup>
