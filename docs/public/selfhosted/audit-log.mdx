## What you'll accomplish

After this guide, you can open the workspace audit log, filter events, and understand which actions are recorded.

## Prerequisites

- Signed in as a workspace **owner** or **admin**
- On self-hosted instances, the audit log is always available — there is no plan gate

## Open the audit log

<Steps>
  <Step title="Go to Settings">
    From the sidebar, select **Settings**.
  </Step>
  <Step title="Open Audit log">
    Under **Administration**, choose **Audit log**.
  </Step>
</Steps>

The audit log is read-only. Only workspace admins and owners can view it.

## What the audit log records

The log captures significant workspace actions: who performed an action, what entity was affected, and when it occurred. Event types include:

| Type | Examples |
|------|----------|
| **auth** | Sign-in and security-related events |
| **bookmark** | Create, update, delete |
| **folder** | Folder changes |
| **tag** | Tag changes |
| **member** | Invitations, role changes, removals |
| **team** | Team create, update, delete |
| **settings** | Workspace configuration changes |

## Filter and search

Use the toolbar to narrow results:

- **Search** — text filter across log entries
- **Entity type** — filter by event category
- **Actor** — filter by workspace member

Click **Clear** or **Clear filters** to reset. Pagination shows which range of events you are viewing.

## Verify it worked

Perform a visible action (for example, rename the workspace under **Workspace → General**) and confirm a new **settings** entry appears in the log.

## Troubleshooting

### Empty log

A new workspace may have no entries yet. Perform an admin action and refresh.

### I cannot open Audit log

You need owner or admin role. Members without admin rights do not see this page.
