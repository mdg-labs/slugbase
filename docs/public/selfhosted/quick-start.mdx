## What you'll accomplish

After this guide, you will have a running self-hosted SlugBase instance reachable over HTTPS, ready for [first workspace setup](/selfhosted/first-workspace-setup).

## Prerequisites

- A Linux or macOS host (or any environment that runs Docker)
- **Docker** installed and running
- **PostgreSQL** reachable from the host — a container or managed service is fine
- A domain name (or local hostname) for HTTPS in production
- Secrets ready to generate: `SESSION_SECRET` and `ENCRYPTION_KEY` (each at least 32 bytes — for example `openssl rand -hex 32`)

<Callout kind="danger">
Never commit real secrets to version control or paste them into documentation. Use a secrets manager or an `env` file with restricted permissions on the host.
</Callout>

## Architecture overview

SlugBase self-hosted uses one **combined image** that serves the API and web client on a single port (default `3000`). PostgreSQL stores all workspace data. A reverse proxy in front of the container terminates TLS and forwards traffic.

## Step 1 — Prepare PostgreSQL

Create a database and role for SlugBase. Example connection string shape:

```bash
DATABASE_URL=postgresql://slugbase:YOUR_PASSWORD@postgres:5432/slugbase
```

The API applies schema migrations automatically on startup.

## Step 2 — Configure environment variables

Create an environment file on the host (for example `slugbase.env`). Minimum runtime keys:

| Variable | Purpose |
|----------|---------|
| `SESSION_SECRET` | Signs server-side sessions |
| `ENCRYPTION_KEY` | Encrypts sensitive settings at rest |
| `DATABASE_URL` | PostgreSQL connection string |
| `APP_BASE_URL` | Public HTTPS URL users open in the browser |
| `FRONTEND_ORIGIN` | Same origin as `APP_BASE_URL` on the combined image |
| `PUBLIC_REGISTRATION` | `false` for invite-only (recommended default) |
| `EMAIL_VERIFICATION_REQUIRED` | `false` unless you configure SMTP first |

<Callout kind="tip">
On self-hosted, workspace administrators can configure **SMTP** and **OIDC** from **Settings → Workspace** after setup. Leave Stripe, Turnstile, and hosted analytics keys empty — those interfaces are no-ops on self-hosted.
</Callout>

## Step 3 — Pull and run the image

Pull the published image from GitHub Container Registry and start the container:

```bash
docker pull ghcr.io/mdg-labs/slugbase:latest

docker run -d \
  --name slugbase \
  --env-file /path/to/slugbase.env \
  -p 3000:3000 \
  --restart unless-stopped \
  ghcr.io/mdg-labs/slugbase:latest
```

Replace the image reference with a specific version tag (for example `v1.0.0`) in production instead of `latest`.

<Tabs>
  <Tab title="Docker Compose">
    A typical Compose stack runs PostgreSQL alongside SlugBase. Point `DATABASE_URL` at the `postgres` service hostname, mount your `env` file, and publish port `3000` (or only expose it to your reverse proxy).

    ```yaml
    services:
      postgres:
        image: postgres:16
        environment:
          POSTGRES_USER: slugbase
          POSTGRES_PASSWORD: CHANGE_ME
          POSTGRES_DB: slugbase
        volumes:
          - slugbase_pg:/var/lib/postgresql/data

      slugbase:
        image: ghcr.io/mdg-labs/slugbase:latest
        env_file: ./slugbase.env
        ports:
          - "3000:3000"
        depends_on:
          - postgres

    volumes:
      slugbase_pg:
    ```
  </Tab>
  <Tab title="Behind a reverse proxy">
    Terminate TLS at nginx, Caddy, or Traefik. Proxy HTTPS traffic to `http://127.0.0.1:3000`. Set `APP_BASE_URL` and `FRONTEND_ORIGIN` to your public `https://` URL so cookies and CORS match what users see.
  </Tab>
</Tabs>

## Step 4 — Verify health

Confirm the container is responding:

```bash
curl -sS http://127.0.0.1:3000/health
curl -sS http://127.0.0.1:3000/version
```

Both endpoints should return success. If the database is unreachable, check `DATABASE_URL` and network connectivity before continuing.

## Step 5 — Complete initial setup

Open your public URL in a browser. On a fresh instance you are redirected to **Set up your instance** (`/setup`).

Follow [First workspace setup](/selfhosted/first-workspace-setup) to create the instance administrator and your first workspace.

## Verify it worked

- `/health` and `/version` respond
- The browser shows the setup wizard (first install) or sign-in (if setup already completed)
- After setup, you can sign in and land on **Home**

## Troubleshooting

### Container exits immediately

Check logs with `docker logs slugbase`. Missing `SESSION_SECRET`, `ENCRYPTION_KEY`, or `DATABASE_URL` prevents startup.

### Database connection errors

Confirm PostgreSQL accepts connections from the container network, credentials match `DATABASE_URL`, and the database exists.

### Redirect or cookie issues behind a proxy

Ensure `APP_BASE_URL` and `FRONTEND_ORIGIN` use the same `https://` hostname users type in the browser. Configure your proxy to forward `X-Forwarded-Proto` and `Host` correctly.

### Setup screen says the instance is already configured

Setup runs once per deployment. Sign in with the administrator account created during setup, or restore from backup if you are rebuilding.
