## What this is for

Self-hosted SlugBase sends transactional email through **SMTP Email Configuration** on the **Settings** admin page (the sidebar label is **Settings**; the in-page section title is **SMTP Email Configuration**). You use it for flows such as password reset, email verification, and optional **Send invite email** when creating users.

## Before you start

- You need access to **Admin** (see [Workspace admin overview](/selfhosted/admin-overview)).
- Have your mail provider’s host, port, credentials, and allowed **From** address. Many providers require an app-specific password or SMTP relay setup.

<Callout kind="tip">
  Environment variables for secrets like `JWT_SECRET` are documented in [Configuration](/selfhosted/configuration). SMTP itself is managed in the app as described here, not via Postmark-style env vars used in some hosted deployments.
</Callout>

## How to configure SMTP

<Steps>
  <Step title="Open Settings" icon="settings" titleType="p">
    Under **Admin**, choose **Settings**.
  </Step>
  <Step title="Enable SMTP" icon="toggle-left" titleType="p">
    Turn on **Enable SMTP**.
  </Step>
  <Step title="Enter server details" icon="server" titleType="p">
    Fill **SMTP Host**, **Port** (often **587** for STARTTLS), **Username/Email**, and **Password**. If a password is already stored, the field may be masked—enter a new value only when you want to change it.
  </Step>
  <Step title="From identity" icon="mail" titleType="p">
    Set **From Email** and **From Name** as your recipients should see them.
  </Step>
  <Step title="TLS" icon="lock" titleType="p">
    Toggle **Use TLS/SSL** to match your provider’s requirements.
  </Step>
  <Step title="Save" icon="save" titleType="p">
    Select **Save SMTP Settings**.
  </Step>
</Steps>

## How to send a test message

The form shows your signed-in account email as the test destination. Select **Send Test Email** to verify delivery. If it fails, the app surfaces an error—double-check host, port, TLS, and credentials.

## Verify

- Run **Send Test Email** successfully.
- Create a user with **Send invite email** ([Members](/selfhosted/admin-members)) and confirm the message arrives, or trigger a password reset from the login screen.

## Troubleshooting

<ExpandableGroup>
  <Expandable title="Add User never offers Send invite email" default-open="false">
    The invite option appears only when the server reports SMTP as enabled. Complete **Settings** → SMTP, save, then try **Add User** again.
  </Expandable>
  <Expandable title="Test email fails with authentication errors" default-open="false">
    Confirm the username and password match what your provider expects (often a full email address and an app password). Try the opposite **Use TLS/SSL** setting if your port is 465 vs 587.
  </Expandable>
  <Expandable title="No email address on file for Send Test Email" default-open="false">
    The test uses your profile email. Ensure your account has an email set, or use another flow (for example invite a different address) once SMTP works.
  </Expandable>
</ExpandableGroup>
