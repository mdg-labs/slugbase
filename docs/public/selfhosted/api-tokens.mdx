## What you'll accomplish

After this guide, you can create a personal API token, use it to authenticate API requests, and revoke tokens you no longer need.

## Prerequisites

- Signed in to your account
- Basic familiarity with HTTP APIs and Bearer authentication

API tokens are **not plan-gated** — every account can create tokens on self-hosted instances.

## Create a token

<Steps>
  <Step title="Open API tokens">
    Go to **Settings → Account → API tokens**.
  </Step>
  <Step title="Start creation">
    Click **New token** or **Create token**.
  </Step>
  <Step title="Name the token">
    Enter a **Token name** that identifies where you use it (for example `backup script` or `CI import`).
  </Step>
  <Step title="Copy the token">
    SlugBase shows the token **once**. Click **Copy token** and store it in a password manager or secret store. You cannot view it again.
  </Step>
</Steps>

<Callout kind="danger">
Treat API tokens like passwords. Anyone with a token can act as you until it is revoked. Never commit tokens to source control or paste them into chat.
</Callout>

## Use a token in API requests

Send the token in the `Authorization` header:

```http
GET /bookmarks HTTP/1.1
Host: your-instance.example.com
Authorization: Bearer YOUR_TOKEN_HERE
```

Use your instance's public API base URL. See the [self-hosted API reference](/selfhosted/api-reference/selfhosted-openapi.yaml) for available endpoints.

API tokens authenticate as your user account. Requests use your permissions in the **active workspace** — set the workspace context the same way as browser sessions (workspace switch via API where applicable).

## Token behavior

| Topic | Detail |
|-------|--------|
| MFA | Tokens bypass MFA — possession of the token is sufficient |
| Sessions | Tokens do not create browser cookie sessions |
| Scope | Tokens inherit your account permissions in each workspace |
| Revocation | Immediate — revoked tokens fail on the next request |

## Revoke a token

<Steps>
  <Step title="Find the token">
    On **Settings → Account → API tokens**, locate the token by name.
  </Step>
  <Step title="Revoke">
    Click **Revoke** and confirm. The token stops working immediately.
  </Step>
</Steps>

The list shows when each token was created and last used.

## Verify it worked

Call a read endpoint (for example `GET /bookmarks`) with the token. A `200` response confirms authentication. A `401` response means the token is missing, invalid, or revoked.

## Troubleshooting

| Symptom | What to do |
|---------|------------|
| 401 Unauthorized | Check the Bearer prefix, token value, and that the token was not revoked |
| 403 Forbidden | Your account may lack permission for the resource in the active workspace |
| CSRF errors | Cookie sessions require CSRF tokens; Bearer token requests do not use CSRF |
