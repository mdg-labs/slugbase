## When you need this

Configure SMTP when your self-hosted instance sends its own email. Without SMTP, flows that depend on email — member invitations, signup verification, password reset, and email-change confirmation — cannot deliver messages.

## Prerequisites

- Signed in as a workspace **owner** or **admin**
- SMTP server hostname, port, username, and password from your mail provider
- **Settings → Workspace → Email / SMTP** visible in the UI (not operator-managed)

## Configure SMTP

<Steps>
  <Step title="Open Email / SMTP">
    Go to **Settings → Workspace → Email / SMTP**.
  </Step>
  <Step title="Enter server details">
    Fill in **SMTP host**, **Port**, **Security** (None, STARTTLS, or TLS), **SMTP username**, and **SMTP password**. Set **From name** and **From address** for the sender header.
  </Step>
  <Step title="Send a test email">
    Enter a **Test recipient** address and click **Send test email**. Fix credentials if delivery fails.
  </Step>
  <Step title="Save settings">
    Click **Save changes** when the test succeeds.
  </Step>
</Steps>

<Callout kind="danger">
Never paste real SMTP passwords into documentation or commit them to source control. Use your provider's console to rotate credentials if they are exposed.
</Callout>

## Operator-managed email

If your deployment sets `VITE_MAIL_ADMIN_UI=false`, the **Email / SMTP** section shows **Email managed by operator** instead of editable fields. Contact your instance operator to change mail transport settings.

## What SMTP enables

| Message type | When it is sent |
|--------------|-----------------|
| Member invitation | Admin invites someone to a workspace |
| Email verification | New account or email address change |
| Password reset | User requests a reset link |

When SMTP is not configured, the application still runs — email-dependent flows degrade gracefully and indicate that mail is unavailable.

## Verify it worked

A **Test email sent** confirmation appears after a successful test. Trigger a password reset or send a member invitation to confirm end-to-end delivery.

## Troubleshooting

| Symptom | What to do |
|---------|------------|
| Test email fails | Verify host, port, security mode, and credentials. Check firewall rules for outbound SMTP. |
| Messages land in spam | Configure SPF, DKIM, and DMARC for your **From address** domain. |
| Settings page is read-only | Email is operator-managed — adjust deployment configuration instead. |
