## What you'll accomplish

After this guide, you can export your bookmarks for backup or migration and understand the full-instance backup options for self-hosted operators.

## Export your bookmarks

SlugBase export is **lossless** for your accessible bookmarks: each entry includes title, URL, slug, forwarding flag, pinned state, and folder and tag associations by name. An export followed by import into a fresh workspace reproduces your bookmarks, folders, and tags.

Sharing grants and other workspace-level relationships are not included in a personal export — only content you can access as the exporting user.

### Export via API

Use a [personal API token](/selfhosted/api-tokens) to download a JSON export:

```bash
curl -sS -H "Authorization: Bearer YOUR_TOKEN" \
  "https://your-instance.example.com/export/json" \
  -o slugbase-export.json
```

Replace the URL with your instance's API base (`APP_BASE_URL`). The response is a JSON array suitable for import via `POST /import/json`.

See the [self-hosted API reference](/selfhosted/api-reference/selfhosted-openapi.yaml) for import endpoints and request formats.

### Import after export

To restore into the same or another workspace:

1. Obtain a JSON export (SlugBase format) or a Netscape HTML browser export.
2. Import via the API (`POST /import/json` or `POST /import/netscape-html`) or from the onboarding import flow / bookmarks **Import from browser** when available in the UI.
3. Confirm folder and tag names are recreated or matched by name.

## When to export

| Scenario | Recommendation |
|----------|----------------|
| Before leaving a workspace | Export your bookmarks — your content stays with the workspace when you leave |
| Migration to another instance | Export from source, import on destination |
| Periodic user backup | Schedule API export with a stored token |
| Disaster recovery (user content) | Keep dated JSON exports off-instance |

## Full-instance backup (operators)

v1 does not include a built-in backup/restore UI. Operators use two complementary approaches:

### 1. Database volume snapshot

For PostgreSQL deployments, snapshot the database volume or use your provider's backup tool on a schedule. This captures all workspaces, accounts, and settings in one step. Restoring requires database administration outside SlugBase.

### 2. Per-user JSON export

Encourage workspace admins to schedule exports for critical content. JSON export is the documented, round-trip-complete path for bookmark data.

<Callout kind="tip">
Test restore periodically: export from a workspace, import into a test workspace, and verify bookmarks, folders, and tags match.
</Callout>

## Verify export integrity

Open the JSON file and confirm:

- Each object has at least `title` and `url`
- Folder and tag name arrays are present where expected
- Slug and forwarding fields match your live data

Import a sample into a test workspace before relying on an export for disaster recovery.

## Troubleshooting

| Symptom | What to do |
|---------|------------|
| 401 on export | Check API token and `Authorization: Bearer` header |
| Empty export array | You may have no bookmarks in the active workspace, or lack access |
| Import skips slugs | Invalid or duplicate slugs are skipped without failing the whole import |
